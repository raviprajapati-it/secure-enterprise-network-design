CASE STUDY 3 — GLOBAL ENTERPRISE SECURITY & VPN CONFIGURATION
Cheltenham HQ + San Francisco + Dubai + Vancouver

This file preserves the key Cisco configuration examples documented in the
original CT6034 global enterprise network-design project.

The source contains a mixture of full configuration examples and abbreviated
branch templates. Commands are preserved where explicitly documented.

============================================================
1. HQ ROUTER — INTERFACES & ROUTING
============================================================

hostname HQ-R

interface Fa0/0
 ip address 192.168.0.1 255.255.255.0
 no shutdown

interface Se0/3/1
 ip address 10.0.0.1 255.255.255.252
 no shutdown

ip route 192.168.1.0 255.255.255.0 10.0.0.2
ip route 192.168.2.0 255.255.255.0 10.0.0.6
ip route 192.168.3.0 255.255.255.0 10.0.0.10

router ospf 1
 network 192.168.0.0 0.0.0.255 area 0

============================================================
2. HQ ASA FIREWALL
============================================================

hostname HQ-ASA

interface Et0/0
 nameif inside
 security-level 100
 ip address 192.168.0.2 255.255.255.0

interface Et0/1
 nameif outside
 security-level 0
 ip address 10.0.0.2 255.255.255.252

nat (inside,outside) source dynamic any interface

access-list OUTSIDE_IN extended permit tcp any host 192.168.40.10 eq 80

access-group OUTSIDE_IN in interface outside

8. SITE-TO-SITE IPSEC VPN — HQ TO SAN FRANCISCO
============================================================

crypto isakmp policy 10
 encr aes
 hash sha
 authentication pre-share
 group 2

!
! The original academic configuration contained a plaintext lab pre-shared
! key. It is intentionally redacted from this public portfolio repository.
!

crypto isakmp key <REDACTED_LAB_PSK> address 10.0.0.2

crypto ipsec transform-set TS esp-aes esp-sha-hmac

crypto map VPN-MAP 10 ipsec-isakmp
 set peer 10.0.0.2
 set transform-set TS
 match address 101

interface Se0/3/1
 crypto map VPN-MAP

10. DOCUMENTED VPN DESIGN
============================================================

The original design applies the same site-to-site IPsec architecture to:

HQ <-> San Francisco
HQ <-> Dubai
HQ <-> Vancouver

The documented security components include:

- IKE / ISAKMP policy
- AES encryption
- SHA integrity hashing
- Pre-shared authentication
- Diffie-Hellman group 2
- IPsec transform sets
- Crypto maps
- Peer configuration
- Interesting-traffic ACLs

Conceptually:

San Francisco -------- IPsec --------\
                                      \
Dubai ---------------- IPsec ---------- Cheltenham HQ
                                      /
Vancouver ------------ IPsec --------/

============================================================
12. POINT-TO-POINT WAN ADDRESSING
============================================================

The design uses /30 networks for point-to-point links.

Documented examples:

HQ <-> San Francisco
10.0.0.0/30

HQ <-> Dubai
10.0.0.4/30

HQ <-> Vancouver
10.0.0.8/30

The /30 design provides two usable addresses per router-to-router link while
keeping WAN addressing predictable and compact.

============================================================
13. SECURITY ARCHITECTURE
============================================================

The global network follows a layered security model combining:

- Departmental VLAN segmentation
- Inter-VLAN routing
- Cisco ASA security levels
- ACL enforcement
- NAT
- DMZ separation
- Site-to-site IPsec VPN
- Port security
- Trunk restrictions
- Secure inter-branch communication

The firewall architecture separates:

PRIVATE
Internal departmental networks

PUBLIC
External or untrusted connectivity

DMZ
Public-facing enterprise services

14. IMPORTANT CONFIGURATION NOTE
============================================================

These commands are preserved from an academic Cisco network-design project.

The source documentation contains some addressing and configuration
inconsistencies across diagrams, tables, and configuration examples.

This repository intentionally does not silently rewrite those original design
decisions.

Instead, the portfolio separates:

1. Original documented configuration
2. Architecture interpretation
3. Technical review and improvement recommendations

This allows the original implementation evidence to remain traceable while
still supporting professional technical analysis.
